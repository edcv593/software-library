# 软件库

扫描 NAS 软件目录，提供搜索、版本下载、上传、远程下载留存及用户管理。

## 分类与资料管理

1. 使用管理员账户登录，进入“管理面板”或左侧“管理分类与软件”。
2. 点击“新建分类”，填写名称并选择上级分类；可创建空分类和多级目录。
3. 搜索并勾选软件，选择目标分类，点击“移动所选”。“全选当前结果”仅选择当前管理搜索结果。
4. 点击“编辑资料”，设置显示名称、简介、标签、备注，以及许可证、适用系统等自定义信息。
5. 左侧点击分类显示该分类及所有子分类的软件，三角按钮控制展开与折叠。
6. 删除分类会同时删除子分类，弹窗显示受影响数量，并允许指定软件迁移位置。实际文件不会删除或移动。

分类和资料保存在 `LIB_DATA_DIR/config.json`，请持久挂载应用数据目录。自定义资料对可浏览软件库的用户可见，不应填写密码或其他私密凭据。软件资料仍按原始软件名称关联；显示名称修改不影响关联，物理文件改名识别列入后续路线。

## 运行与更新

环境变量及 NAS 挂载示例见 [部署指南](部署指南.md) 和 `docker-compose.yml`。

镜像声明了以下两个持久化目录，支持读取镜像卷声明的 NAS 界面会在创建容器时列出它们：

| 容器目录 | 在 NAS 上选择的文件夹 | 权限 |
| --- | --- | --- |
| `/data` | 存放现有安装包、ISO 等文件的软件仓库 | 只读 |
| `/app/data` | 独立的软件库应用数据文件夹，保存账户、配置、上传文件及下载队列 | 读写 |

拉取镜像只负责下载镜像；目录映射在**创建/重建容器**时设置。已有容器继续使用原来的映射即可。镜像无法替用户选择宿主机目录，也无法强制所有 NAS 界面弹出必填表单；未指定映射时 Docker 可能创建匿名卷。参见 [Docker 卷声明说明](https://docs.docker.com/reference/dockerfile/#volume)。

**首次使用仓库的 Compose 文件部署：**

1. 在 NAS 上准备好上述两个不同的文件夹。
2. 将 `.env.example` 复制为同目录下的 `.env`，填写 `SOFTWARE_DIR` 和 `APP_DATA_DIR` 的绝对路径。也可在支持环境变量的部署界面中填写这两个变量。
3. 先执行 `docker compose config` 检查，然后执行 `docker compose up -d`。

两个路径留空或未设置会在部署前报错；路径不存在时不会自动创建拼错的目录。使用新版 Compose 文件替换旧文件时，请将**原来的两个 NAS 路径**填入 `.env`，以继续读取原有数据。仅更新现有镜像、不更换原部署文件时无需新增 `.env`。

本地运行：

```sh
pip install requests
LIB_ROOT_DIR=/path/to/software LIB_DATA_DIR=/path/to/app-data python app.py --watch
```

Docker 用户备份应用数据后，在 compose 文件所在目录执行：

```sh
docker compose pull
docker compose up -d
```

需等待 GitHub Actions 镜像构建发布成功后更新。已有数据将自动兼容，无需重建用户或清空扫描结果。

本地验证：`python -m unittest discover -s tests -v`。

后续规划见 [优化路线](ROADMAP.md)。

## v10：版本、下载队列与官网更新

### 版本管理

进入软件详情后，管理员可以编辑版本号、适用系统、架构、稳定/测试/历史渠道、更新说明，并设置一个推荐版本。选中文件后使用“合并 / 拆分所选”：填写已有软件的原始名称可合并，填写新名称可拆分；这只改变逻辑归属，不移动 NAS 原始文件。显示名称与原始名称可以不同，目标输入框会提供已有名称。

默认隐藏历史版本，勾选“显示历史版本”可下载旧版。支持版本搜索、日期排序和版本号自然排序（不包含复杂语义版本规则）。从“上传新版本”上传会直接归入当前软件。上传和远程下载的新文件均记录 SHA-256，原有 NAS 文件不会在扫描时额外计算大文件哈希。

### 上传修复

- 浏览器采用分块传输、服务器分块写入，不再一次把整个安装包读进内存；仍兼容标准单文件 multipart 表单。
- 支持多选文件逐个上传、进度和取消；传输完毕后显示“正在入库”，扫描完成才显示已入库。
- 上传文件保存在应用数据的 uploads 目录，同名文件不会覆盖；中断和失败的临时文件会清理。
- 明确拒绝空文件、不支持的类型和超过上限的文件；正常显示网络错误、超时和反向代理返回的非 JSON 错误。
- 修复上传目录嵌套在扫描目录内时被跳过的问题；Web 服务改为多线程，上传时其他请求仍可响应。

默认单文件上传上限 2048 MB，下载上限 8192 MB，可使用 `LIB_MAX_UPLOAD_MB`、`LIB_MAX_DOWNLOAD_MB` 调整。上限按文件本身计算，不含 multipart 表单头。

若使用 Nginx 反向代理且仍出现 HTTP 413，代理自身也需要允许对应大小。例如上传 2 GB 文件可在对应 server/location 中设置 `client_max_body_size 2100m;`，同时按 NAS 的扫描耗时设置 `proxy_read_timeout 600s;`。这些配置不会由应用自动修改；其他代理需使用其对应设置。

### 下载队列

管理员点击顶部“下载队列”，填写安装包直链、所属软件和可选保存文件名；原来的“下载留存”入口也会加入队列。队列在服务器端顺序执行，不依赖浏览器保持打开，显示状态、字节进度、平均速度及错误。

支持取消等待/下载中的任务、手动重试失败或取消的任务、移除已结束记录。取消正在等待远端响应的下载可能需要等待网络超时（约 20 秒）。重试会从头下载，目前不支持断点续传。队列持久保存在 `LIB_DATA_DIR/download_queue.json`：等待任务重启后继续，中断任务标为失败并可重试；已保存但尚未入库的文件会恢复入库流程。

### 官网地址与自动同步

管理员在软件管理列表或版本详情点击“官网与更新设置”，可以维护官网地址、官方下载直链和官网入口显示开关，也可配置：

1. **最新版下载直链**：地址必须始终指向最新版安装包；固定旧版本链接或普通官网首页无法自动定位新版。没有可识别后缀时填写保存文件名。每次检查会下载后对比 SHA-256，相同内容不重复入库，但会消耗下载流量。
2. **GitHub Releases**：填写公开仓库 `owner/repo` 和只匹配一个文件的规则，例如 `*windows*x64*.exe`。读取最新稳定发布的版本号和说明；若发布方提供 SHA-256，也会进行校验。未匹配或匹配多个文件会报错，避免错误选择系统/架构。接口语义见 [GitHub 官方文档](https://docs.github.com/en/rest/releases/releases#get-the-latest-release)。

可以“保存并立即同步”，或为该软件勾选自动检查（默认关闭，间隔可设为 1–720 小时，默认 24 小时）。后台每分钟检查是否到期，并将任务加入下载队列；自动同步失败会记录在队列中，管理员可手动重试。

只有下载完整、类型和可用校验值均通过后，新版才设为推荐，当前软件的旧文件转为历史版本。**“替换最新版”是替换软件库的推荐版本，不会安装/升级服务器上的软件，也不会删除或覆盖 NAS 原始文件。** 旧版文件保留供回退，需按实际空间安排后续清理。单个更新源对应一个系统/架构，需多个架构时建议拆分为独立软件条目。

配置版本和同步来源前请先备份应用数据目录。当前已支持的更新源不能覆盖任意官网；需要登录、验证码或专用更新协议的软件需提供可用直链或另行适配。

### UU 远程与飞牛 fnOS 官网适配

- **UU 远程 Windows**：下载队列现在可以直接填写 `https://adl.netease.com/d/g/uuremote/c/gw?type=pc`。程序从官方页面提取 PC 下载接口，再跟随官方跳转获取安装包，不会把网页保存成 EXE。定时同步可直接选择“UU 远程 Windows 官方最新版”。
- **飞牛 fnOS x86**：更新源选择“飞牛 fnOS x86 官方最新版”，每次从 `https://fnnas.com/download` 获取当前 ISO，并按官网下载按钮的公开流程申请新的临时下载签名。无需手动保存 `sign`、`t` 参数。
- 若在下载队列粘贴飞牛带签名的 ISO 链接，程序会为**同一版本**重新申请签名；要跟随官网升级版本，请使用上述 fnOS 更新源或官方下载页地址。
- 重试时从原始页面重新解析，不复用上一次跳转后的临时地址。当前适配仅覆盖上述 UU Windows 和 fnOS x86 入口，不会执行任意网页脚本；官网改版或需要额外登录时会明确失败，现有版本仍保留。
- 修复自定义信息等编辑弹窗中“保存”按钮白底白字的问题，恢复保存图标，并让底部操作区在窄屏及长表单中保持可见。


### 下载访问控制

软件目录允许访客浏览，本站文件必须登录才能下载（包括复制的下载链接）。
首次创建管理员后，不开放自行注册，账号由管理员在「管理面板 → 用户管理」创建。
普通账号默认允许下载，管理员可点击「暂停下载 / 允许下载」随时调整；暂停会中断正在传输的文件。
默认每个账号最多同时下载 2 个文件，可在下载与流量中调整；超过返回 429，请等待已有下载完成。
删除账号后原登录凭据立即失效。下载响应不允许代理缓存，应用数据目录不再通过网页直接暴露。
旧账号保留原密码与下载权限。更新镜像并重建容器后生效，保留 /app/data 挂载即可保留账号。
这些限制只作用于本站文件，跳转第三方官网的下载不占用本站文件传输带宽。
并发限制与速度上限分别设置，详见下载与流量。


### 管理面板布局

管理面板分为软件管理、分类管理、用户管理、系统设置，左侧和面板顶部均可切换，每次只显示一个功能区。软件管理合并重复列表，每页 20 项，支持搜索和批量归类；官网与更新设置、版本管理位于每个软件的“更多操作”中。


### 11.1：版本识别与下载流量

- 页面底部显示应用版本、构建提交和构建时间。系统设置可检查 GitHub 最近成功发布的构建；查询失败会明确提示，不自动更新容器。
- 「下载与流量」设置本站文件总下载速度（KiB/s）、每账号每日额度（MiB）、每账号并发（1–32），可选择管理员豁免。速度与每日额度默认 0（不限），并发默认 2，升级不改变原账号权限。
- 例如 512 KiB/s 约为 4.2 Mbps；该速度在本应用进程的非豁免账号间共享，并非每个连接各享一份。管理员豁免的流量不计入总限速。
- 每日额度按北京时间 00:00 重置；SQLite 数据库存于 /app/data/traffic.sqlite3，重启保留。额度耗尽会中断当前文件，再次下载返回 429。客户端需要重新下载，不支持断点续传。
- 流量按服务器提交发送的字节计入。为防并发请求或重启绕过额度，发送前预留一个数据块；断线/异常退出时该块（至多 64 KiB）可能未到客户端，仍计入额度。不会按整个文件预扣。
- 管理员可看最近 100 条下载记录，数据库保留最近 1000 条已结束记录及 90 天每日统计；进程异常退出后的下载标记中断。记录从更新后开始生成。
- 用户通过「我的流量」查看当日额度；此接口不暴露其他用户记录。
- 仅约束从本站发送的文件，不限制第三方官网下载或服务器下载留存任务。适用于单容器单应用进程部署。


### 11.2：软件归并与批量操作

软件管理增加「合并建议」，按名称的版本号差异保守匹配，保留 Pro、Server 等产品区别；建议不会自动执行。也可手动勾选两个以上含本地版本的软件，再选择「合并所选软件」。
确认页列出全部版本文件并选择保留的软件。合并只调整逻辑归属，文件不移动、不删除；保留目标软件资料和推荐版本，来源版本的说明与渠道保留，来源推荐标记取消。来源软件配置仍留存在配置文件中，不覆盖目标。
合并后首页显示一张目标软件卡片，全部版本在详情页查看。重新扫描保留结果；需要拆分时可在版本管理中移动版本至原软件名称。新发现的未归并文件仍按扫描规则识别，不会自动套用旧建议。
确认时服务器会再次核对来源版本列表，列表变化则拒绝执行并要求重新确认。软件管理的批量归类和合并按钮仅在勾选软件后出现，「全选当前页」最多选择当前页 20 项。


### 11.3：官网更新审核与回退

「官网与更新设置」新增“下载完成后需管理员批准发布”，默认开启（旧配置未填写该项也按开启处理）。自动检查仍正常下载，但新版先进入待审核，不改变原推荐版本。需要直接自动发布时，可针对软件取消勾选。
管理员在软件详情 → 版本管理中查看待审核文件，可先下载验证，再批准或拒绝。待审核和已拒绝文件不会出现在普通用户的版本列表中，直接下载也受服务器限制。拒绝后文件保留，仅管理员可查看（勾选显示历史版本）。
批准后新版本设为推荐，其他已发布版本转为历史版本，文件不删除。勾选“显示历史版本”，选择“回退到此版本”并确认即可恢复旧推荐；新版本继续保留为历史版本。普通管理员手动上传文件不经过官网更新审核流程。
审核状态在重新扫描和重启后保留。相同内容的官网更新仍会去重，不会因拒绝重复下载相同文件；误拒绝时可点击“重新审核”恢复待审核，再核验和批准。


### 11.4：账号维护与登录保护

11.5 起，下面的密码修改和管理员直接重置入口统一改为邮箱验证码重置，详见后文。

- 用户管理的“更多操作”提供禁用/启用账号和重置密码。禁用阻止登录、使原会话失效，并停止正在进行的下载；启用后需重新登录。下载权限和历史用量保留。管理员不能禁用自己。
- 用户可在顶部账号菜单修改自己的密码，需验证当前密码。管理员重置其他用户密码不需要知道旧密码。修改或重置后，该账号所有设备重新登录。
- 新建或修改的密码要求 8–128 个字符。既有短密码仍能登录；原 SHA-256 记录在成功登录时自动迁移为带独立随机盐的 PBKDF2-SHA256，不需要重新注册。修改后不要部署不支持新密码格式的旧镜像。
- 5 分钟窗口内，同一账号失败 5 次或同一连接来源失败 30 次，将暂时拒绝尝试并返回 429。成功登录清除账号失败计数。失败计数在应用内存中保存，重启会重置。
- 不信任访客传入的代理 IP 请求头。穿透服务若把多个访客映射为同一个来源地址，他们会共享来源失败次数限制；账号限制仍分别计算。


### 11.5：QQ 发件、邮箱注册、绑定与验证码重置

在「系统设置 → QQ 邮箱与账号注册」填写 QQ 发件邮箱、相同的发件人邮箱和 SMTP 授权码，服务器预填 `smtp.qq.com`，端口 `465`，加密 `SSL/TLS`。QQ 邮箱需要先开启 SMTP 服务并生成授权码；授权码不是 QQ 登录密码。可参考 [腾讯的 QQ 邮箱 SMTP 配置说明](https://main.qcloudimg.com/raw/document/product/pdf/1270_46586_cn.pdf)。

- 配置并开启“开放邮箱注册”后，登录弹窗显示“邮箱注册”。注册必须验证收到的邮件验证码；默认无需审批，注册后即可登录下载，适用站点原有每日额度、限速和并发规则。没有另设新账号额度，站点额度为 0 时仍表示不限。
- 原有用户名账号保持兼容。登录后通过账号菜单“绑定邮箱”验证新邮箱；绑定后用户名与邮箱均可登录。每个邮箱只能关联一个账号。
- 登录页“忘记密码”和账号菜单“邮箱重置密码”均要求已绑定邮箱的验证码。重置后所有设备重新登录，禁用状态不会因此解除。管理员不能直接替其他用户设置密码。
- 注册、绑定、重置的验证码按用途隔离，绑定验证码还与当前账号关联。验证码 10 分钟有效、只能用一次、最多错误尝试 5 次；同一用途的同一邮箱 60 秒内不能重发，每个连接来源每小时最多 5 次、全站每小时最多 100 次。发送计数和验证码散列持久保存，重启不清零。
- 关闭公开注册后，已有账号仍可通过已配置的发件邮箱绑定和重置密码。尚未绑定且忘记旧密码的账号不能通过任意邮箱找回，请先妥善绑定。
- 邮箱配置位于 `/app/data/mail-settings.json`（包含发件授权码），验证码散列位于 `/app/data/email-signup.sqlite3`。保留原 `/app/data` 挂载即可保留配置。授权码不会通过接口回传，留空保存表示保持原值。
- 自动测试通过模拟邮件投递验证流程，没有向真实邮箱发送邮件。部署后填写真实授权码，再使用自己的邮箱验证实际投递。


### 11.6：本地 / 115 分享下载

软件详情的管理员操作新增「下载来源」，可为每个版本选择本地文件或 115 分享。请先将同一个安装包上传至 115，再填写 HTTPS 分享链接及访问码；不支持将快捷方式当作安装包，也不会自动上传或删除本地文件。此阶段仍依赖本地文件索引，不能删除本地源文件。

选择 115 后，访客通过站内账号和发布权限检查，点击「确认领取」按该本地索引文件的完整大小预扣每日额度，再获得 115 分享页面链接。文件由 115 发送，本站不代理、不回退本地传输。切换回本地可恢复原下载方式。领取不代表实际下载成功，额度不会因链接失效、取消或未下载自动退还。

每次重新打开领取窗口视为新领取；同一窗口网络重试会使用相同请求标识，7 天内不会重复扣额。后台记录领取次数，额度统计合并本地发送量和网盘预扣量。分享链接发给用户后可能被转发，本站不能继续约束网盘端的下载并发、速度或测量实际流量。

115 的“免登录下载”须在 115 分享设置中开启，并有相应的免登录下载流量额度；普通会员身份不等于向访客提供无限免费流量。参见 [115 官方免登录下载说明](https://q.115.com/115115/T833364.html)。本站仅提供分享跳转，不使用会员 Cookie 或非公开接口。

后续官方 API 接入需要 [115 开放平台](https://open.115.com/) 开发者认证和应用授权，当前不包含自动目录同步、上传迁移或自动生成直链。
# 11.6.1 下载来源填写改进

“下载来源”支持直接粘贴 115 分享整段文字或 Markdown 链接，保存时自动识别链接和访问码。手填访问码优先；多个不同链接或自动识别到冲突访问码时会提示修正。更新链接时清空旧访问码，避免沿用上一条分享的密码。115 来源显示为“分享页面”，是否免登录仍由 115 决定。
