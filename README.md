# 软件库

扫描 NAS 软件目录，提供搜索、版本下载、上传、远程下载留存及用户管理。

## 分类与资料管理

1. 使用管理员账户登录，进入“管理面板”或左侧“管理分类与软件”。
2. 点击“新建分类”，填写名称并选择上级分类；可创建空分类和多级目录。
3. 搜索并勾选软件，选择目标分类，点击“移动所选”。“全选当前结果”仅选择当前管理搜索结果。
4. 点击“编辑资料”，设置显示名称、简介、标签、备注，以及许可证、适用系统等自定义信息。
5. 左侧点击分类显示该分类及所有子分类的软件，三角按钮控制展开与折叠。
6. 删除分类会同时删除子分类，弹窗显示受影响数量，并允许指定软件迁移位置。实际文件不会删除或移动。

分类和资料保存在 `LIB_DATA_DIR/config.json`，请持久挂载应用数据目录。自定义资料对可浏览软件库的用户可见，不应填写密码或其他私密凭据。软件资料仍按原始软件名称关联；显示名称修改不影响关联，物理文件改名识别列入后续路线。

## 运行与更新

环境变量及 NAS 挂载示例见 [部署指南](部署指南.md) 和 `docker-compose.yml`。

本地运行：

```sh
pip install requests
LIB_ROOT_DIR=/path/to/software LIB_DATA_DIR=/path/to/app-data python app.py --watch
```

Docker 用户备份应用数据后，在 compose 文件所在目录执行：

```sh
docker compose pull
docker compose up -d
```

需等待 GitHub Actions 镜像构建发布成功后更新。已有数据将自动兼容，无需重建用户或清空扫描结果。

本地验证：`python -m unittest discover -s tests -v`。

后续规划见 [优化路线](ROADMAP.md)。

## v10：版本、下载队列与官网更新

### 版本管理

进入软件详情后，管理员可以编辑版本号、适用系统、架构、稳定/测试/历史渠道、更新说明，并设置一个推荐版本。选中文件后使用“合并 / 拆分所选”：填写已有软件的原始名称可合并，填写新名称可拆分；这只改变逻辑归属，不移动 NAS 原始文件。显示名称与原始名称可以不同，目标输入框会提供已有名称。

默认隐藏历史版本，勾选“显示历史版本”可下载旧版。支持版本搜索、日期排序和版本号自然排序（不包含复杂语义版本规则）。从“上传新版本”上传会直接归入当前软件。上传和远程下载的新文件均记录 SHA-256，原有 NAS 文件不会在扫描时额外计算大文件哈希。

### 上传修复

- 浏览器采用分块传输、服务器分块写入，不再一次把整个安装包读进内存；仍兼容标准单文件 multipart 表单。
- 支持多选文件逐个上传、进度和取消；传输完毕后显示“正在入库”，扫描完成才显示已入库。
- 上传文件保存在应用数据的 uploads 目录，同名文件不会覆盖；中断和失败的临时文件会清理。
- 明确拒绝空文件、不支持的类型和超过上限的文件；正常显示网络错误、超时和反向代理返回的非 JSON 错误。
- 修复上传目录嵌套在扫描目录内时被跳过的问题；Web 服务改为多线程，上传时其他请求仍可响应。

默认单文件上传上限 2048 MB，下载上限 8192 MB，可使用 `LIB_MAX_UPLOAD_MB`、`LIB_MAX_DOWNLOAD_MB` 调整。上限按文件本身计算，不含 multipart 表单头。

若使用 Nginx 反向代理且仍出现 HTTP 413，代理自身也需要允许对应大小。例如上传 2 GB 文件可在对应 server/location 中设置 `client_max_body_size 2100m;`，同时按 NAS 的扫描耗时设置 `proxy_read_timeout 600s;`。这些配置不会由应用自动修改；其他代理需使用其对应设置。

### 下载队列

管理员点击顶部“下载队列”，填写安装包直链、所属软件和可选保存文件名；原来的“下载留存”入口也会加入队列。队列在服务器端顺序执行，不依赖浏览器保持打开，显示状态、字节进度、平均速度及错误。

支持取消等待/下载中的任务、手动重试失败或取消的任务、移除已结束记录。取消正在等待远端响应的下载可能需要等待网络超时（约 20 秒）。重试会从头下载，目前不支持断点续传。队列持久保存在 `LIB_DATA_DIR/download_queue.json`：等待任务重启后继续，中断任务标为失败并可重试；已保存但尚未入库的文件会恢复入库流程。

### 官网地址与自动同步

管理员在软件管理列表或版本详情点击“官网与更新设置”，可以维护官网地址、官方下载直链和官网入口显示开关，也可配置：

1. **最新版下载直链**：地址必须始终指向最新版安装包；固定旧版本链接或普通官网首页无法自动定位新版。没有可识别后缀时填写保存文件名。每次检查会下载后对比 SHA-256，相同内容不重复入库，但会消耗下载流量。
2. **GitHub Releases**：填写公开仓库 `owner/repo` 和只匹配一个文件的规则，例如 `*windows*x64*.exe`。读取最新稳定发布的版本号和说明；若发布方提供 SHA-256，也会进行校验。未匹配或匹配多个文件会报错，避免错误选择系统/架构。接口语义见 [GitHub 官方文档](https://docs.github.com/en/rest/releases/releases#get-the-latest-release)。

可以“保存并立即同步”，或为该软件勾选自动检查（默认关闭，间隔可设为 1–720 小时，默认 24 小时）。后台每分钟检查是否到期，并将任务加入下载队列；自动同步失败会记录在队列中，管理员可手动重试。

只有下载完整、类型和可用校验值均通过后，新版才设为推荐，当前软件的旧文件转为历史版本。**“替换最新版”是替换软件库的推荐版本，不会安装/升级服务器上的软件，也不会删除或覆盖 NAS 原始文件。** 旧版文件保留供回退，需按实际空间安排后续清理。单个更新源对应一个系统/架构，需多个架构时建议拆分为独立软件条目。

配置版本和同步来源前请先备份应用数据目录。当前已支持的更新源不能覆盖任意官网；需要登录、验证码或专用更新协议的软件需提供可用直链或另行适配。
